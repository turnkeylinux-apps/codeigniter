# CodeIgniter 19.0 testing

## Scope and source decision

Debian 13 Trixie packages CodeIgniter 3.1.13, which does not satisfy this
appliance's existing CodeIgniter 4 contract. CodeIgniter 19.0 therefore uses
the maintained official CodeIgniter 4.7.4 release archive. The build pins the
archive SHA-256, release tag and source commit. PHP 8.4, MariaDB, Apache and
the required PHP modules come from signed Debian Trixie repositories.

CodeIgniter framework updates require an administrator to follow the official
manual upgrade procedure. This is intentional because upstream upgrades can
change application-owned configuration and code. The runtime test checks the
official latest-release redirect without changing the installed application.

## Static and boundary checks

```sh
bash -n conf.d/downloads conf.d/main tests/v19.sh \
  overlay/usr/lib/inithooks/firstboot.d/20regen-codeigniter-secrets
git diff --check
```

Normal firstboot generates a private application database password. The
focused database round trip uses that generated credential to prove that the
updated CodeIgniter configuration and MariaDB account agree. This covers the
normal user-visible framework, database and administration paths before
optional configurations or edge cases.

## Known limitation

Docker runtime validation does not exercise the installer, appliance kernel,
bootloader or physical hardware. CodeIgniter adds no appliance-specific
behavior at those boundaries, so the validated Core 19 baseline supplies
inherited evidence.

## Deferred issues

- The acceptance flow covers the default application, MySQLi database driver
  and built-in CLI. Additional database drivers, custom routes, application
  deployment and email delivery require project-specific configuration.
- Upstream framework upgrades are supervised because configuration and
  application changes can require manual reconciliation.
